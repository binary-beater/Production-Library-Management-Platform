# 0014 - Role-Based Access Control (RBAC)

## Context
The platform serves three distinct user types with completely different capabilities: Administrators, Librarians, and Members. APIs must enforce who can do what — not just whether a user is authenticated, but whether their role authorizes the specific action.

## Decision
We implement **Role-Based Access Control (RBAC)** using FastAPI's dependency injection system.

## Implementation Strategy
```python
# Dependency factories per role
def require_admin(current_user: User = Depends(get_current_user)) -> User:
    if current_user.role != UserRole.ADMIN:
        raise HTTPException(status_code=403, detail="Admin access required")
    return current_user

# Usage at route level
@router.delete("/users/{id}/role")
async def update_role(
    user: User = Depends(require_admin)  # Only admins reach here
):
    ...
```

## RBAC Matrix Summary
| Capability | Admin | Librarian | Member |
|---|---|---|---|
| Manage user roles | ✅ | ❌ | ❌ |
| Add / update / delete books | ✅ | ✅ | ❌ |
| Borrow / return books | ✅ | ✅ | ✅ (own) |
| View all active loans | ✅ | ✅ | ❌ |
| View dashboard analytics | ✅ | ✅ | ❌ |

## Why FastAPI Dependencies vs. Middleware?
- Middleware applies globally — you cannot conditionally apply it per-route.
- FastAPI dependencies compose cleanly: `Depends(require_librarian_or_admin)` is readable, testable, and explicit.
- Each dependency can be mocked in unit tests independently.
